## 推荐的开发顺序（由简到繁）

### 第一阶段：基础骨架（1-2天）

- [x] **项目初始化** + 配置（数据库、JWT、Apifox）
- [x] **统一响应结构** + 全局异常处理
- [ ] **用户注册 + 登录**（最简单的接口，无复杂业务）
- [ ] **JWT 认证过滤器**（让后续接口都能用上认证）

### 第二阶段：核心简单功能（3-4天）

- [ ] **知识库 CRUD**（增删改查，不涉及成员和文档树）
- [ ] **文档 CRUD**（先不做版本、分享、移动等复杂操作）
  - 创建文档、编辑文档、删除文档（软删除）、获取文档详情
- [ ] **个人资料修改** + 修改密码

> 此时你已经有一个可用的笔记系统雏形，可以手动测试。

### 第三阶段：中等复杂度功能（2-3天）

- [ ] **文档树结构**（`parent_doc_id` 的支持，获取知识库下的文档树）
- [ ] **知识库成员管理**（添加/移除成员、角色修改）
- [ ] **收藏 + 点赞**（这两张表结构简单，逻辑清晰）
- [ ] **浏览历史记录**（每次查看文档时插入一条记录）

### 第四阶段：高级功能（3-4天）

- [ ] **文档版本管理**（版本保存、列表、回滚）
- [ ] **分享链接**（生成、密码校验、过期）
- [ ] **回收站**（恢复、彻底删除）
- [ ] **搜索**（简单的 `LIKE` 查询）

### 第五阶段：后台管理 + 统计（2-3天）

- [ ] **后台用户管理**（禁用/启用、重置密码、分配角色）
- [ ] **文档审核**（在 `document` 表加 `audit_status` 字段）
- [ ] **举报处理**
- [ ] **数据统计**（先做实时统计接口，最后再做定时任务填充 `daily_stat`）
- [ ] **系统公告**

### 第六阶段：辅助与优化（1-2天）

- [ ] **文件上传**（供编辑器用）
- [ ] **备份与恢复**
- [ ] **操作日志记录**（可以最后统一加切面或拦截器）

## 为什么不必按接口文档顺序？

| 接口文档顺序 | 实际依赖问题             | 更好的顺序                                 |
| :----------- | :----------------------- | :----------------------------------------- |
| 文档版本管理 | 依赖文档创建/编辑接口    | 等文档 CRUD 稳定后再做                     |
| 分享链接     | 依赖文档详情接口         | 可以后做                                   |
| 后台统计     | 依赖用户、文档等基础数据 | 最后做                                     |
| 回收站       | 依赖删除接口             | 删除功能本身先做软删除，恢复和彻底删除稍后 |

## 核心原则

1. **先做无依赖的，后做有依赖的**（例如先做知识库，再做文档）
2. **先做简单 CRUD，后做复杂业务**（例如先做文档增删改，后做版本回滚）
3. **先做用户能直接感知的核心流程，后做管理后台**（先让用户能用，再让管理员能管）
4. **每个阶段完成后用 Postman 或 Swagger 测试**，确保可用再进入下一阶段
